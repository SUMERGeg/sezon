# ExecPlan 0005 — M3: рабочая корзина

## Goal / Context
Пользователь разрешил завершить этап 3 и реализовать следующий: добавить выбранный вариант/открытку, изменить количество и удалить позицию, сохранить выбор после reload. Источники: `docs/07-data-model.md`, `docs/08-state-and-business-rules.md`, Cart в `docs/05-ui-specs.md`. Существующие client islands и валидированный каталог сохраняются.

## Non-goals
Checkout-форма/доставка (M4), реальные заказы/оплата, backend, персональные данные, новые зависимости.

## Architecture / Data-state impact
Pure cart domain: identity `productId + variantId + greetingCard`, merge, quantity clamp `1..min(9, demoStock)`, текущие цены/итоги из catalog, безопасное чтение persisted rows. Версионированный envelope `{version:1, items}` в `season-cart:v1` содержит только четыре разрешённых поля. Browser store с `useSyncExternalStore`, стабильный server snapshot/loading shell, storage adapter отдельно от UI; изменение вкладок синхронизируется storage event. При недоступном localStorage сохраняется рабочее состояние в памяти и показывается объяснение. Неизвестные/недоступные строки удаляются, количество корректируется с уведомлением.

## UI / Accessibility
Счётчик в шапке; доступный вариант добавляется без смены фокуса, live feedback и ссылка в корзину. Недоступный вариант disabled. Страница: thumbnail/название/размер/гамма/открытка/цена/количество/удаление, subtotal и demo disclosure; доставка рассчитывается на этапе checkout. Empty state ведёт в каталог. Кнопки количества доступны с клавиатуры и ограничены границами. После удаления focus переходит к соседней позиции или empty heading. Адаптив 390/1440, статусы доступны assistive tech. CTA ведёт к существующей demo-checkout заглушке с честным пояснением.

## Acceptance criteria / Tests
- Повторное добавление объединяет одинаковую строку; размер или открытка создают отдельную.
- Остаток/лимит не превышаются; decrement не удаляет; remove явно удаляет.
- Reload восстанавливает безопасные IDs/опции, а не persisted цены/контакты.
- Corrupt JSON, invalid rows, unknown IDs, unavailable stock и blocked storage не ломают UI.
- Unit tests domain/storage; E2E product → add → reload → cart → qty/remove/empty, tampered storage, keyboard, console/overflow 390/1440.
- Lint/typecheck/build и relevant suites проходят.

## Risks / Decisions
Основные риски — hydration mismatch и доверие localStorage. Server shell не выдаёт ложных итогов; storage schema и актуальный каталог ограничивают данные. Небольшой native React store выбран вместо новой библиотеки. Checkout завершится отдельным этапом.

## Outcome
2026-10-01: M3 готов. Domain/schema/storage в отдельных слоях, React external store без новой зависимости; server snapshot стабилен. Работают add/merge/options, qty limits, remove/focus return, subtotal/header count, reload и storage events. Persisted payload содержит только 4 разрешённых поля. Corrupt JSON и invalid/stale rows корректируются, blocked storage оставляет memory cart. Checkout-заглушка обновлена, чтобы не утверждать, что корзина пуста.

Проверки: production build, lint и typecheck — exit 0; 36 unit tests (8 новых cart), 13 relevant E2E (cart + storefront-ui) и 1 ожидаемый desktop skip mobile dialog. Проверены keyboard/add focus/remove focus, 390/1440 screenshots, отсутствие console errors/overflow. Независимый read-only review без доказуемых P0/P1. E2E подготовка corrupt storage теперь ждёт hydration перед записью, чтобы исходная страница не успевала очистить fixture до reload. Checkout-форма/доставка/завершение demo остаются M4.
